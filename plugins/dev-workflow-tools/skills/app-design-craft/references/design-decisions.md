# 設計モード：⓪方向性 ＋ 最初に決める6つ

新しい画面やアプリの見た目を作り始める前に、⓪で方向を決め、続く6つを確定する。
順番に作ってから整えようとすると、後から一貫性が崩れて手戻りが大きい。
**方針を1枚のメモ（デザイントークン的なもの）にしてから実装に入る。**

各項目に「なぜ先に決めるか」「決め方」「nemuiasaの選択」を載せる。

---

## ⓪ 方向性のコミット（①〜⑥より先に決める）

**なぜ:** ①〜⑥は「決めた方向をどう実現するか」の道具であって、**方向そのものは決めてくれない**。
方向を言語化しないまま始めると、無意識に「無難で穏当な平均」に着地する。
ポートフォリオが増えるほどこれは深刻で、**どのアプリも同じ顔になるのは配色ミスではなく、この⓪を飛ばしていることが原因**。

**決め方:**

**1. 8方向から1つ選び、振り切る。** 混ぜない。中間を取らない。

| 方向 | 手触り | 向くジャンル |
|---|---|---|
| calm / serene | 静けさ・余白・低彩度 | 記録、習慣、睡眠、瞑想 |
| playful / energetic | 弾む動き・原色・丸み | 学習、子ども向け、ゲーム的 |
| premium / refined | 暗い地・細い線・寡黙・金属質 | 資産、健康、ハイエンドな道具 |
| utilitarian / focused | 装飾ゼロ・情報密度・速さ | 業務、計算、変換、開発者向け |
| editorial / magazine | 明朝/セリフ・大見出し・段組 | 読み物、レシピ、旅、ニュース |
| brutalist / raw | 太線・ベタ・粗さ・非対称 | ニッチ、尖った個人向け、SNS |
| warm / organic | 手描き・紙・くすみ色・不揃い | 日記、家計、子育て、暮らし |
| cold / technical | 等幅・グリッド・蛍光1色・暗背景 | 計測、ログ、位置、電波 |

**2. ポートフォリオ内の既存アプリと方向がかぶっていないか確認する。**
`$PRD_VAULT_DIR/portfolio.yml`（デフォルト `~/dev/business/prd-vault/portfolio.yml`）と既存アプリのスクショを見て、
**直近に出した2本と同じ方向なら選び直す。** それでもかぶせるなら、なぜ今回はかぶってよいのかを1行で説明できること
（例：同一シリーズとして意図的に揃える）。説明できないかぶりは、ただの惰性。

**3. 選んだ方向の帰結を1行ずつ書き出す。**
「この方向だから背景は◯◯」「この方向だから動きは◯◯」「この方向だから、やらないことは◯◯」。
帰結が3つ書けない方向は、まだ選べていない。

**4. ⑥（世界観の核）はこの方向の具体化として書く。** ⓪が上位、⑥がその言語化。

> **振り切るとは「派手にする」ではない。** utilitarian に振り切るなら装飾ゼロまで行く。
> calm に振り切るなら本当に何も置かない。どの方向でも、**中途半端が一番凡庸**。

**nemuiasaの選択:** calm / serene に全振り。
これは**ひとつの解**であって基準ではない。全アプリをここに寄せた時点で⓪は死ぬ。

---

## ① パレット（色）

**なぜ:** 色は後から足すほど散らかる。最初に「使える色」を制約として決めると、全画面が自動的に揃う。

**決め方:**
- ベース（背景）1〜2色：純白より少し温度のあるオフホワイト/クリーム、または少し青みの白など、世界観に合わせる。
- テキスト：ほぼ黒〜濃グレー＋階層用のグレー2〜3段。
- **アクセント1色（多くて2色）**：CTA・選択状態・重要バッジにだけ使う「意味のある色」。
- 「この色は何に使う色か」を全色について言えるようにする。役割のない色を作らない。

**nemuiasaの選択:** オフホワイト＋ほぼ黒、アクセントはアプリごとに1色（ondot=赤）。

> アクセントを増やしたくなったら、まず「サイズ・余白・太さ」で差をつけられないか考える。色は最後の手段。

---

## ② スペーシングスケール（余白）

**なぜ:** 半端な間隔（7px, 13px…）が混ざると無意識に「雑」に見える。一定の刻みに乗せるだけで整って見える。

**決め方:**
- 基準単位を決める（iOSなら 4 or 8）。それの倍数だけ使う：4, 8, 12, 16, 24, 32, 48…
- 「要素内（パディング）」「要素間」「セクション間」で段階を割り当てる。
- 画面四辺の余白を固定（例：水平16〜20pt）。

**nemuiasaの選択:** 余白を最優先し、たっぷりの間とゆったりした行間。カード内パディングも大きめ。

---

## ③ タイポの役割（書体）

**なぜ:** 書体は人格。役割を決めずにサイズだけ変えると締まらない。

**決め方:**
- ファミリーは1〜2種に絞る（本文用＋必要なら表現用）。
- **役割で型を作る**：Display（特大見出し）/ Title / Body / Label（極小キャプス）/ Caption。サイズ・ウェイト・字間・行間をセットで定義。
- 和文＝伝える主役（大きな日本語見出し）、欧文＝洗練の小ラベル（オールキャプス）の使い分けを意識。
- 書体の温度を世界観に合わせる：明朝＝静・余韻、丸ゴシック＝親しみ、幾何サンセリフ＝モダン。

**nemuiasaの選択:** プロモは特大・太字の日本語1〜2行。UIラベルは英字の極小オールキャプス。hibiは明朝＋括弧と字間で静けさ。

---

## ④ 唯一の強調装置

**なぜ:** 強調手段が画面ごとに違うと、視線の学習が効かず散漫になる。「最重要はこう光る」を1つ決めると、全画面で一目で要点が伝わる。

**決め方:**
- 最も時間/意思決定に効く情報（締切・残数・CTA・選択状態）を、**ひとつの一貫した装置**で強調する（例：塗りつぶしの黒ピル／アクセント色の塗りボタン）。
- その装置は1画面に1〜2回まで。増やすと強調が無効化する。

**nemuiasaの選択:** 締切・当落など時限情報を「塗りつぶしの黒ピル」で1点強調。

---

## ⑤ ボイス（言葉のトーン）

**なぜ:** UIコピーはデザインの一部。声が揺れるとブランドが揺れる。

**決め方:**
- 主語を「ユーザーの体験/得」に置く（機能名でなくベネフィット）。
- 敬語/タメ口、硬さ、絵文字の可否を決めて全画面で守る。
- **使わない言葉リスト**を作る（煽り語・常套句・流行語で世界観に合わないもの）。何を言わないかが個性になる。
- マイクロコピー（空状態・エラー・プレースホルダ・ボタン）の基本トーンも決める。

**nemuiasaの選択:** 体験を語る柔らかな日本語。"参戦"のような常套句をあえて使わない。媚びない誠実さ。

---

## ⑥ 世界観の核（ひとことルール）

**なぜ:** 個々の判断に迷ったとき立ち返る基準。1フレーズで言えると全接点で再現できる。

**決め方:**
- アプリの世界観を1フレーズに凝縮する（例：「日常にそっと寄り添う、静かでやわらかい」）。
- そのフレーズを、色・余白・書体・言葉・モーション・アイコン・ストアスクショ・空状態すべての判断基準にする。
- 「このフレーズに照らして、この要素はアリか？」を最終チェックに使う。

**nemuiasaの選択:** 「余白を大切にした、静かでやわらかなデザイン。日常にそっと寄り添う」を全接点で体現。

---

## 方針サマリの書き出し例

決めた⓪と6つは、こういう短いメモにして実装の拠り所にする：

```
# <アプリ名> デザイン方針
方向性:    premium / refined（直近2本 <アプリA>=calm, <アプリB>=warm と重複なし）
世界観の核: 「<ひとことルール>」
パレット:  base=#F7F5F0 / text=#1A1A1A / gray=#8E8E93,#C7C7CC / accent=#E1483B(意味:重要/CTA)
スペース:   8の倍数。画面余白=20 / カード内=16 / セクション間=32
タイポ:    Display 34/Bold, Title 22/Semibold, Body 17/Regular, Label 11/Semibold/英字キャプス
強調装置:  最重要=塗りつぶし黒ピル（1画面1回）
ボイス:    体験を主語に・敬語・絵文字最小。使わない語=「参戦」「神アプリ」「爆速」
```

このメモができたら `swiftui-recipes.md` でコードに固定する。
