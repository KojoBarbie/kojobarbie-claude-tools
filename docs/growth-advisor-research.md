# AI による「主体的グロース提案」スキル — 調査＆設計メモ

> 作成: 2026-07-04 / deep-research（Web検索ファンアウト → ソース取得 → 主張の敵対的検証 → 引用付き合成）の結果と、それを踏まえたスキル自作の設計方針をまとめたもの。
> 別セッションで同種の検討を進めているとのことなので、そちらと突き合わせるための素材。

## 構想（何を作りたいか）

特定のアプリのリポジトリを探索し、「このアプリがもっと売れる/成長するには」という観点で、
新機能・グロース施策・収益化・マーケなどを **主体的（プロアクティブ）に提案する** Claude Code スキル。

---

## 結論（要点）

- 「AI がプロダクト開発・グロースを主体的に提案する」取り組みは、2026年時点で **国内外に活発に存在する**。
- ただし大半は **「PM/マーケの知識・フレームワークを符号化し、ユーザーが呼び出すと発動する“指示パッケージ”」** の形。
- 構想している **「任意のアプリのリポジトリを自律探索 → 売上/グロース/収益化/マーケ施策を主体的に提案する一気通貫エージェント」は、明確な“空白地帯（ギャップ）”** だった。
- 部品（コードを読む技術／グロース提案の知識）はほぼ揃っているのに、両者を「コード探索 → ビジネス提案」へ橋渡しする統合スキルが見当たらない。**＝ 作る価値がある領域。**

---

## ① 取り組みの状況（国内外の実例）

海外は「PMスキルのマーケットプレイス」が一大ジャンル化している。

| 実例 | 内容 | 構想との距離 |
|---|---|---|
| **phuryn/pm-skills**（PM Skills Marketplace, MIT） | Claude Code を「PM OS」化。68〜100+スキル/9プラグイン。`pm-go-to-market`（グロースループ・ICP）、`pm-marketing-growth`（ポジショニング・North Star）、`pm-product-strategy`（Lean Canvas・価格戦略・競合分析）、`monetization-strategy` 等。Teresa Torres / Marty Cagan / Alberto Savoia 等のフレームワークを符号化 | 提案の中身（グロース/収益化）は網羅。**ただしコードを読まず会話入力で動く** |
| **alirezarezvani/claude-skills**（345+スキル, MIT, 13プラットフォーム） | PM・グロース・マーケ系を多数含む。特に **`code-to-prd`（既存コードベースから PRD を逆生成）** が「コード探索」側の部品 | コード探索の部品 + 戦略提案の部品が **両方ある。が、両者を繋いだ統合スキルは無い** |
| **coreyhaines31/marketingskills**（11万+インストール） | CRO・コピー・SEO・analytics・グロースエンジニアリング。SEO Audit 単体で1.3万+インストール | マーケ施策の部品。リアクティブ（要求時参照）型 |
| **Every の Compound Engineering プラグイン**（~21kスター） | **最も構想に近い。** `/ce:strategy`（Rumelt の戦略論で対話的に戦略文書を生成）、**`/ce:product-pulse`（PostHog/Mixpanel/Stripe/Sentry 等の実データを統合し、製品健全性レポートと追加調査を自律生成、`~/pulse-reports/` に蓄積）** | 「実データ駆動で主体的に提案」に最接近。**ただし“コード静的解析”ではなく“分析データ統合”が起点** |

国内（日本）は周回遅れ気味。代表例は CodeZine「Claude Agent SDK で自律型“コードの考古学者”を作る」記事（Gitログ・変更頻度から設計意図を文書化）だが、**出力はコード調査レポート止まり**で、グロース提案には踏み込んでいない。**国内発の体系的なグロース提案スキル集は確認できず → ここも空白。**

## ② コード探索 → ビジネス提案を実現する既存スキル

「ある」けれど「欲しい形そのもの」は無い、という状態。

- **コードを読むスキルは存在する** — `code-to-prd`（コード→PRD逆生成）、pm-skills の `/document-app`・`/ship-check`（文書化・監査・テストカバレッジ）、Every の `/ce:product-pulse`（分析データ統合）。
- **しかしその出力は、文書化・監査・PRD逆生成・分析レポート止まり。** 「コード分析の結果を売上・収益化・PMF 戦略の提案に橋渡しする」スキルは確認されなかった（複数リポジトリを直接インベントリして2回確認、いずれも "None identified"）。
- **自律計画エージェント**（Devin 2.0 の Interactive Planning＝開始時にコードを先回りスキャンして計画提示／Claude Skill "Ralph"＝PRD実装ループ）も**あるが、対象は「コードタスク」であって「ビジネス/グロース提案」ではない**。

> コードを自律探索する技術も、グロース提案の知識も揃っているのに、**両者を1本に繋いだものが空席** ＝ このスキルのポジション。

## ③ 周辺トレンドと、設計に効く知見

- **学術的裏付け（ASE 2024, arXiv:2408.17404）** — 「アプリ説明を LLM に与えて新機能を提案させる手法」vs「App Store マイニング（競合分析）」を1,200サブ機能で比較した査読論文。**LLM は特に“新規・未開拓の領域”で機能提案が強力**と実証。ただし**実現可能性不明な“空想的”機能も混じり、人間レビュー前提**。→ 「提案する」こと自体は学術的に裏付けあり、**ただし人間の検証ステップは必須**。
- **最重要の実装知見（uxdesign.cc, 2026/4「AIはコードを読めても製品を知らない」）** — AI に「新機能をブレストして」と頼んだら1分で「通知センター/アクティビティフィード/分析ダッシュボード/オンボーディングウィザード」など**汎用 SaaS 機能を返したが、どれも製品のコア体験に合わず全却下**。対策として著者は `.claude/skills/<product>-context/` という **「製品コンテキスト注入」ディレクトリ型スキル**（`SKILL.md`=ルーター, `design.md`, `pointers.md`, `quickref/`, `references/`）を自作。**→ 自作スキルの設計テンプレとして直接参考になる。**
- **反証された主張（誇張として棄却）** — 「エージェントAIが完全自律でPMタスクを自己起動する」「コードは製品文脈の40%しか持たない」等のベンダー系主張は 0-3 / 1-2 で棄却。**“完全自律・自己起動”は現状ハイプ**で、**人間が起点・検証に関わる半自律が現実的**。

## ④ 自作スキルへの示唆（設計方針）

このリポジトリの流儀（フェーズ立て・移植性重視・特定リポジトリ非依存）に沿う形で:

1. **2段階入力にする** — ❶コード探索（構造・依存・機能棚卸し）だけでは不十分。❷**製品コンテキスト**（誰向け/コア体験/ビジネスモデル/現状の指標）を README・`.kiro/steering` 等から読む or 1〜2問だけ対話で補う。uxdesign.cc の失敗を回避する肝。
2. **提案は“主体的だが検証前提”** — ASE 2024 の知見通り、空想機能を弾くため「各提案に根拠・前提・検証実験（pretotype/計測指標）をセットで出す」。pm-skills の `monetization-strategy`（提案＋検証実験を出す）が良い型。
3. **出力カテゴリを分けて主体提案** — 新機能 / グロース施策 / 収益化・価格 / マーケ・GTM / PMF 仮説、のように軸を切ると多角的に提案できる。
4. **既存スキルを車輪の再発明しない** — `code-to-prd`・Every の `/ce:product-pulse`・pm-skills の戦略フレームワークは部品として参考にし、**独自価値は「コード探索 → 製品コンテキスト統合 → 多軸グロース提案」という“繋ぎ”に置く**（ここが世界的にも空白）。
5. **移植性** — feature-planning/ship-issue と同様、対象リポジトリ名やスタックはハードコードせず実行時に取得。

---

## 留意点（リサーチの限界）

- この分野は超高速で動いており、スキル数・バージョンはスナップショット値（pm-skills は調査中に 65→68→100+ と変動）。「実在・活発」という結論は安定。
- 中核証拠は単一メンテナのGitHub/著者ブログが多め（自己宣伝トーンあり）。ただし複数の並行リポジトリ・独立メディア・査読論文で相互裏付け済み。
- **未解明**: 「リポジトリ自律探索→収益化/グロース提案」を一気通貫でやるエージェントが本当に皆無か、非公開の社内/ステルス製品として存在するかは調査の射程外。
